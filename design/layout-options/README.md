# 常驻布局候选

本目录保留1536×864布局方案的设计来源。用户最终选定A紧凑版，游戏界面已完成实施，最新实测见项目根目录`TEST_REPORT.md`。

共同约束：主页面不滚动；状态栏和资产清单全部展开且不滚动；常驻内容中仅完整记录可滚动。当前工作区的长内容允许局部滚动，主操作按钮固定。清单按商品种类、设备与在制任务汇总，不展开库存批次。三张图均展示17类货物、全部7类设备、在制品和住房。

- A：左资产、中工作区、右完整记录。空间均衡，记录可见条数最多。
- B：顶部横向资产，下方工作区与记录。资产总览最直观，工作区纵向空间较少。
- C：左侧大工作区，右上资产、右下完整记录。操作空间更宽，记录窗口较短。

已实施：取消分页，改为工作区内部滚动；移除市场进出按钮并同步共享规则及遭遇触发；情报在追问/核对后才展示相应信息，同步保护公共接口；加入固定资产清单和完整记录区域。B、C作为历史备选保留在生成脚本中。

`layout-a.png`、`layout-b.png`、`layout-c.png` 为图片，配套HTML可在浏览器查看，`render.mjs` 可重新渲染，`metrics.json` 记录页面尺寸与固定资产区域溢出检查。

## A 紧凑版（用户选定 A 后的第二稿）

`layout-a-compact.png` / `layout-a-compact.html`：缩小页边距、压紧顶部状态栏和两侧清单。示意图中左资产236px、右记录252px，中间1008×732px；原A中间为842×668px，宽度增加约20%。实际游戏为适配页眉控件采用1008×720px的中栏。资产及状态完整可见且不滚动，完整记录允许滚动，工作区长内容局部滚动，夜间入口固定。保留14px正文字号。

## 重新生成

在项目根目录安装依赖后执行（需要本机Chrome）：

```sh
node design/layout-options/render.mjs
node design/layout-options/render-a-compact.mjs
```

必须按上述顺序执行，紧凑版以首个脚本生成的A版HTML为输入。脚本与本说明进入Git；生成的`layout-*.html`、`layout-*.png`和`metrics*.json`只保留在本机，不提交。游戏实际界面的验证截图由`npm run test:browser`生成到`tests/browser-output/`。
