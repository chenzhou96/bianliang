# 《汴梁归途》连续时间与商人生活更新计划

本计划把连续昼夜、市场买卖和住宅生活作为一次整体更新。用户已确认引入时间资源、取消独立晚间界面、允许熬夜并递增健康和体力代价，且不需要兼容旧存档。下列具体时长、价格、公式与数量为首轮实现和模拟的基准参数，允许根据验收结果调整，不应视作已经验证的平衡结论。

文档前半部分说明体验、规则取舍和实施顺序；后半部分为逐项验收清单。具体数值是可调整的设计基准，验收项需有实际证据才能勾选。既有实施过程单独保存在 [实施记录](../archive/CONTINUOUS_TIME_IMPLEMENTATION_LOG.md)。

## A. 更新目标与玩家循环

让不从事生产的玩家，也能依靠观察行情、判断消息、组织搬运、承接收购和经营客户关系稳定成长。住宅提供仓储、保鲜、待客和睡眠方面的不同收益，让买房后的生活持续有选择。

每一天的基本循环是：查看时钟与已知行情 → 安排采购、交货和生活 → 在交易收益与耗时之间取舍 → 傍晚决定是否参加夜市或邀请客户 → 按身体状况选择睡眠 → 查看睡眠期间的变化，继续经营。

时间、体力、健康分别承担不同职责：时间决定能赶上哪些机会，体力决定当下能够负担的劳动量，健康与睡眠不足承接长期作息后果。点击界面、查看信息和思考不收费，玩家可以从容制定计划；有实际世界结果的行动才推进时间。

本轮保留生产行业、已有商品和客户、租房到置业以及长期归乡目标。不设置总天数上限。地图移动、雇员排班、贷款和独立店铺经营放到后续版本，避免同时扩大管理负担。

## B. 连续昼夜的交互规则

### B1. 一个时钟贯穿全部工作区

顶部常驻“第几日、几点几分、时段、困倦程度”。白天、傍晚、夜间沿用相同导航与操作位置，背景和提示随时间柔和变化。进入夜间不跳页、不强制结算，也不要求点击“进入晚上”。玩家关闭游戏后时间停止。

行动按钮旁显示耗时。重要操作预览需要包含开始和完成时刻、现金变化、体力消耗、营业窗口，以及途中可能发生的腐坏或生活费用。失败操作不扣时间、资源或随机数；正式开始后按时间轴处理确定事件，完成时才取得交易收益。

信息页在闭店后仍可阅读，交易按钮说明“明日08:00开市”，并提供等待到营业。普通等待不恢复体力；可随时回住所安排休息或睡眠。等待到下一事件的快捷方式必须有清晰终点，单次不超过24小时。

### B2. 城市有营业节奏

| 场所或活动 | 首轮时间窗口 | 设计作用 |
| --- | --- | --- |
| 普通市场、脚夫、劳动、学习、房屋设备交易 | 08:00—18:00 | 白天安排主要经营，脚夫帮助赶收市 |
| 茶馆 | 09:00—21:00 | 在交易前后都可获取消息 |
| 客户业务 | 08:00—20:00 | 留出收市后交付的时间 |
| 夜市 | 18:00—24:00 | 有限货盘与特殊采购机会 |
| 食肆 | 06:00—24:00 | 自行安排正餐，无强制晚饭页面 |
| 住宅待客 | 18:00—22:00 | 用晚间时间经营客户关系 |
| 居家生活、住宿 | 全天 | 支持早睡、午休、夜班等作息 |

恰好在闭店时完成允许，晚一分钟完成则不能开始该交易。系统应根据整项行动的预计完成时间判断，不让玩家支付后才发现正常交易无法完成。夜市和客户营业窗口不同，不能把所有晚间活动统一锁死。

### B3. 日历与生活周期分开

午夜只推进日期；每日06:00更新行情、生活账单、养殖和当日机会。主餐和喂养采用06:00到次日06:00的周期，避免23:59吃饭后00:00立刻又要求吃一次。

生产与腐坏按实际经过的分钟推进。今天17:00开始的24小时加工，正常情况下明天17:00完成。暂停设备不继续加工；凉储改变腐坏速度而不重置货龄。长睡和等待必须依次经过所有中间时点，不能仅在终点一次性补算。

## C. 休息、睡眠和熬夜

### C1. 将奖励按钮改为资源交换

“休息一下”明确改为“休息1小时，恢复20体力”。可以重复，但会占用营业时间，无法清除睡眠不足。主餐、加餐、治疗和睡眠同样有清晰的耗时与恢复说明；加餐每日前两次生效，重复主餐不重复奖励健康。

睡眠提供8小时、睡到下一次07:00和自选1—10小时。确认前显示预计醒来时刻、住宿费、体力恢复和期间将经过的账单或订单时点。睡眠不暂停市场、生产、腐坏、自动喂养和契约倒计时。

### C2. 递增代价必须可预见

- 睡眠不足以小时累计：清醒每小时增加0.5，睡眠每小时减少2，限制在0—12小时。每小时不足使体力上限下降3，最低保留30。
- 连续清醒满18小时后，行动体力倍率逐渐上升；单次睡满4小时才重置连续清醒记录，短睡仍可以恢复体力和部分睡眠不足。
- 22:00以后逐步提高体力消耗，02:00以后开始递增健康损失；清醒超过24小时有额外健康代价。具体公式见后文验收清单，按分钟累计，拆成多个小动作不能规避。
- 夜间睡眠恢复效率较高，白天降低到80%。升级卧房改善体力恢复，不消除熬夜规则，也不能让长期不睡觉成为稳定最优解。

22:00提示“夜已深，继续活动会更费体力”；02:00提示明确健康风险。提示在经过时点时触发，不用每点击一次就弹窗。零体力仍能进食、休息、睡眠和等待，零现金仍有免费住宿选择。

### C3. 熬夜必须有真实理由

偶尔为了赶一笔夜市货盘、交付窗口或客户约定而晚睡，可以有经济收益；连续熬夜需要付出恢复时间、健康和次日经营机会。夜市不能每天提供必买的超额回报，否则正常睡眠会成为错误选择。模拟时同时比较资产、健康与睡眠不足，不能仅凭现金增长判断平衡。

## D. 专注买卖的成长路线

### D1. 市场信息足够支持决策

商品详情统一呈现最近14日行情、当前买卖价、持仓批次成本、含运费保本价、预计净利、临期数量和可售余量。关注与持仓筛选帮助商人聚焦少量品类；预留口粮和饲料后再计算“可售余量”。图表配文字记录，信息不能只靠颜色传达。

商品页关联玩家已经取得的消息、公开收购和已知客户需求。情报存在延迟、减弱、落空等情况，事后允许回看判断；界面与公开工具不能暴露隐藏事件结果。

### D2. 三种搬运方式形成经营选择

自搬适合小额低成本交易，推车适合频繁周转，脚夫适合大宗或赶时间。每笔交易包含10分钟固定办理时间，再按货重计算搬运时间、体力和费用。采购运费进入批次成本，销售及交付运费计入交易费用，收益展示口径保持一致。

推车首轮300文、不占住宅功能位；脚夫最低10文且只在白天营业。货房减少搬运时间，住宅因此直接改善商人效率。单笔数量变化必须实时更新预览，最大可买卖量同时考虑现金、仓位、体力与营业时间。

### D3. 机会、关系与长期目标

每日生成2条限量收购，公开价格、数量和截止，可分批完成。每日最多1组日间货盘和2组夜市货盘；货盘整体采购，公开内容、折扣、鲜度和总搬运负担。机会由种子和周期确定，重开页面和读档不能刷新。首轮折扣5%—15%，夜市每组不超过240文，降低新商人参与门槛。

客户关系3解锁提前预告，6解锁一条延长至次日12:00的收购预留，10解锁大宗货盘及该客户第四段专属后续故事；六位客户分别编写，只有实际拜访后才能回看。关系上限10，满级待客仍可读未完成的居家故事，但不继续增加关系。没有新内容的拜访不刷关系，避免重复点击取代实际经营。里程碑围绕首笔盈利、累计贸易净利、整批采购、脚夫交付、连续盈利和深交客户，每项首次达成奖励一件永久纪念物及短故事，分别为第一枚盈余钱、千文旧账册、首批货签、脚夫交讫牌、五日红账笺、熟客留名帖。达成时提示，商人生涯可回看；纪念物不占仓位、不兑换现金，按达成时刻记录且只授予一次。

希望形成三种可行方向：粮食大宗依靠周转和搬运效率；贵货依靠信息和资金安排；鲜货依靠时机、凉储和快速交付。订单和生产仍可混合，但纯商人不应被迫打工或开工坊才能生存。

## E. 住宅成为生活和经营的结合点

设备位升级为共享功能位，生产设备与生活设施竞争空间。小屋阶段需要选择，置业提供扩展余地。设施可以拆卸封存、重装或按购价60%出售，暂时退租不抹掉已拥有资产。

| 设施 | 初始价格 | 占位 | 主要收益 |
| --- | ---: | ---: | --- |
| 货房 | 400文 | 1 | 基础仓储容量增加40%，搬运时间减少20% |
| 凉储 | 600文 | 1 | 保护20单位易腐货物，腐坏速度减半 |
| 会客间 | 500文 | 1 | 邀请已结识客户，解锁居家故事和关系收益 |
| 卧房 | 350文 | 1 | 睡眠体力恢复增加15% |

凉储按玩家品类优先级、再按临期顺序分配，空位自动补充。调换货物不重置保鲜时间。住房失效或欠维护时停用加成和生产，超容量只限制新增库存，不销毁已有货物。

待客花费20文和60分钟，包含当周期主餐；同客户每3日一次，只有新剧情提供关系奖励。首轮为6位客户各写2段居家后续，并加入入住小屋、置业、首次待客、推车、脚夫和夜市相关的一次性生活事件。故事应解释关系变化和经营生活，避免把住宅做成另一组每日领奖按钮。

每日06:00扣住房费，新入住不重复扣本周期费用。客栈按一次睡眠收费，外宿仍承担已有住宅账单。醒后摘要汇总生产完成、腐坏、养殖、房费和行情变化，并可收起，不强迫玩家阅读长日志才能继续操作。

## F. 实现结构与存档策略

唯一权威时间为绝对游戏分钟。日期、时段、生活周期、截止、冷却、加工剩余和食品寿命统一以此计算，避免日计数与分钟各自结算。所有界面和WebMCP调用同一行动预览、校验与执行规则。

规则拆分到时间、行动耗时、统一结算、住宅、市场机会和存档校验模块；引擎负责组织行动与状态变更，页面只负责输入和呈现。公开接口只返回玩家已知的信息。交易开始预留现金或货物，完成后转移；健康归零时结束游戏，未完成交易不产生收入。

本次按新版本存档开发，不编写v1/v2迁移逻辑。使用独立v3存储键，发现旧档时说明需重新开始；不自动覆盖或删除原始旧档。新档也必须严格校验版本、字段、数量、时间与引用完整性，损坏数据不能静默修复后产生资产。

## G. 分阶段实施与交付物

| 阶段 | 主要工作 | 阶段交付与退出条件 |
| --- | --- | --- |
| 1：统一时间基础 | 状态、时段、营业、行动耗时、纯预览、新档 | 边界规则测试通过，浏览不推进时间，失败无副作用 |
| 2：连续结算与生活 | 替换夜间总清算，睡眠、用餐、喂养、疲劳、生产和腐坏 | 长动作经过多个时点正确，无独立夜间入口，拆分操作无收益漏洞 |
| 3：商人循环 | 搬运、成本与行情、收购货盘、关系解锁 | 小额和大宗完整交易可玩，机会有限且确定，账目可核对 |
| 4：住宅和内容 | 四设施、共享位、待客故事、资产与费用 | 租住、升级、封存、欠费、重装全流程通过，事件不重复领奖 |
| 5：界面整合 | 昼夜视觉、提醒、睡醒摘要、桌面与移动布局 | 真实浏览器覆盖所有工作区和最长内容，主要操作可达 |
| 6：平衡与发布验收 | 六策略模拟、熬夜对照、完整回归、报告 | 下列验收门槛满足，记录实际结果和未解决问题后再判定完成 |

各阶段都同时更新状态、界面、存储和公开接口，不能只完成画面而保留旧规则。经济参数集中配置；先跑固定种子基线，再逐项调整收益或成本，保留调整前后的可比较结果。

## H. 平衡方法与验收口径

正式模拟至少采用30个固定种子，每个种子运行100日，分别测试粮食大宗、贵货、鲜货、订单、生产和混合策略；策略只能读取玩家可知的信息。另用一致决策规则比较正常睡眠与主动熬夜。

记录存活率、现金、净资产、健康、睡眠不足、交易利润、住房和推车达成日、货损、费用、空等时间与拒绝动作原因。净资产口径应包括库存的可变现价值及资产回收价值，扣除债务，避免把购房购设施误判为亏损；所有策略使用同一计价口径。增长倍数在双方增长中位数为正时比较，负增长策略直接列为平衡失败，不用绝对值掩盖。

首轮目标：贸易策略存活率至少80%；稳健贸易净资产增长中位数为正；30日前至少一半种子能租房并购车；最佳贸易与生产的净资产增长中位数差不超过2倍；长期熬夜不能同时在资产、健康、睡眠不足上优于正常作息。若失败，应回到价格差、搬运负担、机会窗口和住房成本定位原因，不靠删除失败样本通过验收。

浏览器覆盖1536×864、1920×900、1920×1080及390×844。重点验证白天自然进入夜间再睡醒、关门前后交易、临期运输、零现金、低体力、无住所、欠费、多订单与最长故事。桌面主要操作不依赖整页滚动，手机允许纵向滚动但不得横向溢出，键盘焦点和禁用原因必须可用。

最终交付包括游戏更新、回归与模拟脚本、逐项勾选的清单和如实记录结果的TEST_REPORT.md。计划与设计参数不等于已通过验证；测试报告只填写实际运行结果。

## I. 典型体验与重点风险

以一位专注买卖的玩家为例：08:00查看持仓与公开收购，比较自搬和推车的完成时间；上午采购并交货，中午花30分钟吃饭；下午根据已知消息选择持货或出清，17:00收到临近收市提醒。傍晚可以去夜市，也可以回家待客；22:00看到继续活动的体力代价，决定是否为一笔有限利润延后睡眠。睡醒后先看到房费、加工、货损和行情摘要，再安排下一天。上述是体验示例，实际可做多少事由数量、搬运和休息时间决定，不保证整套活动能全部完成。

实施时优先防止以下问题：

| 风险 | 处理原则 | 验收方式 |
| --- | --- | --- |
| 时间变成频繁点等待 | 提供到营业、睡到早晨的快捷选择；信息浏览不限时 | 实际操作检查闭店到重新营业流程 |
| 商人被体力和生活费挤出经营 | 按真实数量计算搬运，保留周转资金，提供不同规模的收购 | 分品类记录存活、利润、发展速度及拒绝原因 |
| 夜市成为必须熬夜的每日奖励 | 货盘有限且不保证划算，代价预先可见 | 对照正常与熬夜策略，检查资产和身体状态 |
| 住房只有固定数值升级 | 共享功能位，使生产、仓储、保鲜和待客有取舍 | 小屋与院落分别验证安装、封存及经营路径 |
| 午夜、清晨和行动完成重复结算 | 使用同一时间轴及固定同刻顺序 | 每个关键边界前后一分钟、长动作和拆分动作回归 |
| 新规则说明不足 | 按钮显示耗时，预览解释费用与失败原因，摘要呈现实际结果 | 无住所、低体力、临期和欠费状态下真实浏览器检查 |

规则正确性、基本商人生存、连续昼夜和存档隔离属于发布前必须完成的内容；剧情润色与数值调整可以迭代，但不能用它们替代核心规则验收。若模拟只能让某一贸易路线较快发展，需要明确记录路线差异，不能宣称所有路线成长速度相同。
