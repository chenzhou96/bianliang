# 汴梁归途项目完成度复核

日期：2026-09-09。结论：部分完成，不能按 EXPANSION_PLAN.md 全量验收。网页具有统一的宋体、青绿色和纸面视觉风格，六个工作区已经接通，但主要布局要求、情报内容和部分数据正确性仍未完成。

本次未修改产品源代码或发布网站。读取了关联任务的最新完成声明，对当前本地生产构建进行独立浏览器检查，使用隔离浏览器存储，未触碰用户真实存档。截图为原始视口截图。结果见 result.json。

## 主要发现

### P1：桌面一屏布局未实现

位置：app/page.tsx:154（商品列表）、app/globals.css:10–20（工作区、列表和底栏）。

计划明确要求1536×864及以上页面和面板均无滚动，不得裁切内容。实测如下（单位px）：

| 工作区 | 1536×864 页面高度 | 1920×900 页面高度 | 1920×1080 页面高度 |
|---|---:|---:|---:|
| 市场 | 2067 | 2067 | 2067 |
| 生产 | 1374 | 1374 | 1374 |
| 住宅 | 980 | 980 | 1080 |
| 人物 | 1020 | 1020 | 1080 |
| 情报（空） | 864 | 900 | 1080 |
| 账本（初始） | 917 | 917 | 1080 |

1536×864下，市场“安排今晚”所在底栏底边为1954px，生产为1261px，均不在首屏。列表没有分页，没有计划中的详情侧栏；账本明确使用内部滚动。顶部叙事与标题占用约390px，实际商品区起点约580px，首屏只能看见少量商品。应重新分配工作区高度，采用分页和详情侧栏，并固定晚间操作入口。见1536-市场.png、1536-生产.png。

### P1：三万文入口无确认覆盖已有存档

位置：app/page.tsx:898。

复现：开始3000文游戏并产生存档 → 刷新回到首页 → 点击“挑战三万文”。实测原存档改变、目标变30000，确认框数量为0。该按钮直接调用start(30000)，而3000文入口会检查已有存档。应统一保护所有新局入口，确认时保留用户选择的目标。

### P1：茶馆120条内容与语义去重不成立

位置：lib/game/content.ts:789–801、lib/game/engine.ts:827–845。

40个种子各复制3次得到120个对象，同一组三个对象的叙述变体完全相同。正文直接插入内部英文semantic。第一次付8文听消息，三条均为船工的grain-rain，仅措辞不同，截图intel.png可见。

候选在更新intelSeen之前一次slice(0,3)，同批没有语义去重；没有具体行情方向、原因或真实配方信息供玩家判断。情报页没有追问、回访入口。应提供真实内容，按批去重，并将线索连接具体规则。当前不能视为120条有效情报已经完成。

### P1：交易成本重复累计，账本利润错误

位置：lib/game/engine.ts:795–805、app/page.tsx:617–620。

隔离规则复现：初始800文，进入市场，买1份药材花113文，再卖出收97文，剩784文，实际亏16文。ledger.tradeCost却为226，tradeRevenue为97，页面公式得到亏129文。原因是买入时记录采购成本，卖出时又把同一成本加进tradeCost。应分离采购现金流与已售成本，并检查生产销售是否同时混入贸易收入。

### P2：经营所需信息和操作入口不完整

位置：app/page.tsx:144–233、269–343、389–415、514–521。

市场没有平均成本、临期时间、预计卖出盈亏。生产未展示成品保质期、具体所需设备及技能修正后的真实消耗，体力文案有多余“$”。购买、学习、开工的禁用条件未完整覆盖现金、原料、体力等限制，也没有跨劳累阈值的事前提示。

住宅按钮用!higher禁止降级，页面无主动退租入口；设备只有拆卸封存，没有固定折价出售入口。旧存档虽保留独立键，但没有计划要求的导出入口。应逐条补齐或明确标记未完成。

### P2：移动端仅做到外层不溢出，交易仍依赖横滑

位置：app/globals.css最后一个媒体查询。

390×844外层页面宽度正常，但市场表格最小宽度720px；数量和买卖按钮位于右侧，需要横滑。首屏约750px才开始表格，几乎没有可操作交易内容。建议移动端使用商品卡片或主列表加交易详情。截图390-市场.png。

### P1：经济与验收报告不能支持“按计划完成”

位置：TEST_REPORT.md:14–28、tests/simulate.ts:246。

计划要求至少100组相同种子比较七策略，现有为每策略30组（总210局不等于100组七策略对照）。报告中劳动30/30在121日达到3000文，酿造165.5日，其余路线0/30；随后却写“劳动收益明显慢于有效生产/经营”，与表格证据相反。计划平衡参考是80–120日达到30000文，报告改写成3000文。

这些脚本策略不足以证明每条产业都不可盈利，但也无法证明计划已达成。应改正报告，完成更有效的公开信息策略和100组对照，再讨论经济平衡。

## 本次通过与覆盖边界

- npm test：9/9通过；typecheck、lint、build、git diff --check通过。
- 六个工作区在三个指定桌面尺寸及390×844手机尺寸均能打开；本次浏览器pageerror为0。
- 验证了首次茶馆内容、已有存档被三万文入口覆盖，以及独立引擎药材买卖账本错误。
- 本次未重复210局模拟，所述平衡结果来自当前仓库报告；未全面重跑四条产业链、最长事件、所有结局和100天情报统计，因此这些项目不标为通过。
- 既有tests/browser.mjs只在1440×1050进行桌面截图，工作区检查只断言panel存在，移动端只断言页面没有横向溢出，未检测桌面页面高度、面板滚动或关键按钮是否在视口内。

建议修复顺序：存档覆盖、账本计算 → 桌面工作区布局与移动交易 → 情报内容及去重 → 缺失经营入口及费用预览 → 经济对照与重新验收。
